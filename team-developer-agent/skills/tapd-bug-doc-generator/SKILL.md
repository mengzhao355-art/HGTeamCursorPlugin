# TAPD Bug Doc Generator (Chrome DevTools MCP → 筛选 → 抓详情 → 生成文档)

## 工具要求

**必须使用 Chrome DevTools MCP** 完成浏览器操作与页面抓取：通过 MCP 的 `list_pages` / `navigate_page` / `take_snapshot` / `click` 等能力打开 Chrome、访问 TAPD、筛选缺陷并逐条打开详情弹窗抓取内容。

## 自动启动 Chrome（无需人工点开）

为确保 Chrome DevTools MCP 可以稳定连接，优先用下面命令启动一个**带远程调试端口**且**独立用户目录**的 Chrome 实例。

在 Windows 上执行（PowerShell / CMD 均可）：

```bash
"C:\Program Files\Google\Chrome\Application\chrome.exe" --remote-debugging-port=9222 --user-data-dir="%USERPROFILE%\.chrome-debug-profile"
```

要点：

- **不要重复启动多个 9222 端口实例**：若已启动，直接复用该实例并继续用 MCP 连接。
- **首次启动需要重新登录 TAPD**：因为使用了独立的 `--user-data-dir`；后续会复用登录态。
- 若 Chrome 不在默认路径：将命令里的 `chrome.exe` 路径替换为本机实际安装路径。

## Quick start (执行清单)

- [ ] 用命令行启动 Chrome（`--remote-debugging-port=9222`）
- [ ] 使用 **Chrome DevTools MCP** 连接到已启动的 Chrome，并开始导航/抓取
- [ ] 通过 MCP 导航到 TAPD，确认已登录（已登录态可复用）
- [ ] 打开目标项目缺陷列表（如外视镜项目）
- [ ] 设置筛选：处理人=当前登录用户；状态∈新/接受(处理)/重新打开
- [ ] 在筛选后的列表中逐条打开缺陷详情弹窗并抓取字段（可用 `take_snapshot` 解析）
- [ ] 在 **BUGFIX** 目录下生成**一份**结构化 Markdown，文件名带当前日期（年月日）

## 约定与输出

### 目标筛选条件

- **处理人**：当前登录用户
- **状态**：新、接受/处理、重新打开
- **范围**：以 TAPD 列表页当前分页为准（如需全量，逐页翻页重复抓取）

### 输出位置与命名

- **目录**：当前工作区根目录下的 **BUGFIX** 文件夹；若不存在则**先创建**该文件夹。
- **文件**：仅输出**一份**结构化 Markdown 文档。
- **命名**：`外视镜项目-当前用户-Bug详情-YYYY-MM-DD.md`（用当前日期替换 `YYYY-MM-DD`，例如 `2026-03-18`）。

> 若用户指定了其他项目名或日期格式，优先遵循用户指定；否则使用上述命名，保存到 `BUGFIX/` 下。

## 环境准备（Chrome DevTools MCP + Chrome）

1. 通过 **Chrome DevTools MCP** 列出/连接 Chrome 页面，或导航到 `https://www.tapd.cn/`。
2. **确保已登录**到用户账号（可通过 `take_snapshot` 确认头像/昵称等）。
3. 若多账号/多租户：确保进入正确的组织/空间后再继续。

## 打开缺陷列表（外视镜项目）

通过 Chrome DevTools MCP 在已打开的 Chrome 中操作：

1. 从 TAPD 顶部导航进入 **项目/空间** → 选择 **外视镜项目**（或使用 `navigate_page` 直接访问列表 URL）。
2. 进入 **缺陷** → **缺陷列表** 页面。

已知列表 URL（可直接访问，若仍有效）：

- `https://www.tapd.cn/tapd_fe/30689687/bug/list?confId=1130689687001002009`

> 若 URL 失效或参数变化：以 UI 导航为准，不要依赖旧 queryToken。

## 设置筛选（处理人 + 状态）

### 处理人 = 当前登录用户

1. 点击 **过滤**。
2. 在过滤条件里找到 **处理人**。
3. 选择 **当前登录用户**（或选择下拉中与当前账号一致的人员）。
4. 应用后确认列表计数变化（例如从 543 → 192）。

### 状态 ∈ 新/接受(处理)/重新打开

优先方式（在页面上直接多选状态）：

1. 在过滤条件里找到 **状态**。
2. 多选：**新**、**接受**（或页面显示为“接受/处理”）、**重新打开**。
3. 应用过滤。

备选方式（若页面不支持多选或 UI 不易操作）：

- 先只做“处理人=当前登录用户”的过滤，再在本地文档里**按状态字段二次筛选**并标注“本页数据”。

## 抓取每条缺陷详情（弹窗预览）

TAPD 常见行为：在列表中点击标题会打开**同页弹窗预览**（URL 会出现 `dialog_preview_id=bug_...`），不一定跳转到独立详情页。

对每一条 Bug（建议按列表顺序）执行：

1. 在列表中点击该条 **标题链接**打开详情弹窗。
2. 在弹窗中定位两个核心区域并抓取文本：
   - **详细信息**：前置条件、测试步骤/复现步骤、实际结果、预期结果等（字段名可能因项目模板不同）。
   - **基础信息**：状态、发现版本、模块、优先级、严重程度、处理人、预计开始/结束、重现规律、迭代、创建人、创建时间、修复人、解决方法等。
3. 若存在附件区：
   - 记录附件文件名、上传人、上传时间（必要时附预览链接）。
4. 关闭弹窗，继续下一条。

### 建议抓取字段（标准化）

每条 Bug 至少输出这些字段（没有就写 `-`）：

- **TAPD ID**
- **标题**
- **状态**
- **发现版本**
- **模块**
- **优先级**
- **严重程度**
- **处理人**
- **预计开始 / 预计结束**
- **重现规律**
- **迭代**
- **产品序列号**（若存在）
- **创建人 / 创建时间**
- **修复人**（若存在）
- **解决方法/解决方案**（若存在）
- **详细信息（原文）**：前置条件 + 测试/复现步骤（保留原始段落与编号）
- **附件（若存在）**

## 生成最终 Markdown 文档

- 只生成**一份**文档，包含列表总览 + 每条详情 + 说明。
- 保存路径：`<工作区根目录>/BUGFIX/外视镜项目-当前用户-Bug详情-YYYY-MM-DD.md`（创建 BUGFIX 目录后再写入）。

输出结构建议：

1. **列表总览表**（一页/多页都可合并到同一个表；建议包含：标题、发现版本、严重程度、预计结束、优先级、状态、创建人、创建时间）
2. **每条 Bug 详情分块**（固定字段表 + 详细信息原文 + 附件列表）
3. **说明**（数据范围、筛选条件、抓取时间、是否仅本页等）

## 质量检查（生成后自检）

- [ ] 汇总表条数与列表页一致（或在“说明”里明确只覆盖第 X 页）
- [ ] 每条 Bug 至少有：标题、状态、优先级、严重程度、处理人、创建时间
- [ ] 详细信息尽量保留原文（含步骤编号与预期/实际）
- [ ] 附件信息不丢失（文件名/上传人/时间）

## 常见问题与处理

- **点击标题不跳转，只出现弹窗**：正常；以弹窗内容为准抓取。
- **状态字段显示为“接受/处理”**：在文档里统一归并到“接受/处理”即可。
- **页面不支持多选状态**：先用“处理人=当前用户”，再在文档里按状态二次筛选并明确“本页数据”。
- **BUGFIX 目录不存在**：在写入文档前先创建 `<工作区根目录>/BUGFIX`，再保存 Markdown 文件。
