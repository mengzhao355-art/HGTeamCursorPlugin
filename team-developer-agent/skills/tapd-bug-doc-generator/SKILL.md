# TAPD Bug Doc Generator (Chrome DevTools MCP → 确认范围 → 筛选 → 抓详情 → 生成文档)

## 工具要求

**必须使用 Chrome DevTools MCP** 完成浏览器操作与页面抓取：通过 MCP 的 `list_pages` / `navigate_page` / `take_snapshot` / `click` 等能力打开 Chrome、访问 TAPD、筛选缺陷并逐条打开详情弹窗抓取内容。

## 执行前对话确认（必做）

在启动 Chrome、连 MCP 或打开具体缺陷列表之前，若用户**未**在同轮对话中写清下列项，必须先通过**一轮（或合并）提问**与用户对齐；用户已全部说明则可跳过对应项。

| 项 | 确认内容 |
|----|----------|
| **项目/空间** | TAPD 项目名称，或**缺陷列表页完整 URL**，或「从首页自行点进某项目」的明确名称 |
| **处理人** | 默认「当前登录用户」还是指定人员（姓名） |
| **状态** | 默认：新、接受/处理、重新打开；若用户要其他状态集合，以用户为准 |
| **数据范围** | 仅当前列表第一页 / 第 1～N 页 / 全量逐页 / 仅指定 **Bug ID 列表**（或标题关键词检索后子集） |
| **输出命名** | 文档中展示的项目名（用于标题与文件名前缀）；日期格式默认 `YYYY-MM-DD` |

**合并提问示例（可直接对用户说）：**

> 请确认：① TAPD 项目名或缺陷列表 URL；② 处理人（默认当前登录用户 / 指定谁）；③ 缺陷状态要哪些；④ 要拉全部分页还是只本页或前 N 条、或只指定若干 Bug ID；⑤ 生成文档里用的项目显示名（用于文件名）。

用户确认后再执行 Quick start；**禁止**在未确认项目入口时默认使用下文「可选示例 URL」。

## 自动启动 Chrome（无需人工点开）

为确保 Chrome DevTools MCP 可以稳定连接，优先用下面命令启动一个**带远程调试端口**且**独立用户目录**的 Chrome 实例。

在 Windows 上执行（PowerShell / CMD 均可）：

```bash
"C:\Program Files\Google\Chrome\Application\chrome.exe" --remote-debugging-port=9222 --user-data-dir="%USERPROFILE%\.chrome-debug-profile"
```

要点：

- **不要重复启动多个 9222 端口实例**：若已启动，直接复用该实例并继续用 MCP 连接。
- **首次启动需要重新登录 TAPD**：因为使用了独立的 `--user-data-dir`；后续会复用登录态。
- 若 Chrome 不在默认路径：将命令里的 `chrome.exe` 路径替换为本机实际安装路径。

## Quick start (执行清单)

- [ ] **已与用户确认**「执行前对话确认」中的必要项（或用户本轮已写清）
- [ ] 用命令行启动 Chrome（`--remote-debugging-port=9222`）
- [ ] 使用 **Chrome DevTools MCP** 连接到已启动的 Chrome，并开始导航/抓取
- [ ] 通过 MCP 导航到 TAPD，确认已登录（已登录态可复用）
- [ ] 打开**用户指定项目**的缺陷列表（用户提供的 URL，或 UI 导航进入该项目 → 缺陷 → 缺陷列表）
- [ ] 按**已确认条件**设置筛选（处理人、状态等）
- [ ] 在筛选后的列表中逐条打开缺陷详情弹窗并抓取字段（可用 `take_snapshot` 解析）
- [ ] 在 **BUGFIX** 目录下生成**一份**结构化 Markdown，文件名带当前日期（年月日），前缀使用**用户确认的项目显示名**

## 约定与输出

### 目标筛选条件（默认值；以对话确认为准）

- **处理人**：默认当前登录用户；若用户指定他人，在过滤中选该人员
- **状态**：默认 新、接受/处理、重新打开；以用户确认为准
- **范围**：以 TAPD 列表页当前分页为准，或在「说明」中写明第 1～N 页；用户指定仅若干 ID 时，只抓取对应行/详情

### 输出位置与命名

- **目录**：当前工作区根目录下的 **BUGFIX** 文件夹；若不存在则**先创建**该文件夹。
- **文件**：仅输出**一份**结构化 Markdown 文档。
- **命名**：`<项目显示名>-<范围简述>-Bug详情-YYYY-MM-DD.md`（例如 `某某项目-当前用户-Bug详情-2026-03-18.md`）。`<项目显示名>`、`<范围简述>` 取自用户确认；若用户未指定范围简述，可用 `当前用户` 或 `指定ID` 等与筛选一致的后缀。
- **日期**：`YYYY-MM-DD` 为生成日；若用户指定其他日期格式，以用户为准。

> 用户指定了其他文件名规则时，优先遵循用户指定；否则使用上述规则，保存到 `BUGFIX/` 下。

## 环境准备（Chrome DevTools MCP + Chrome）

1. 通过 **Chrome DevTools MCP** 列出/连接 Chrome 页面，或导航到 `https://www.tapd.cn/`。
2. **确保已登录**到用户账号（可通过 `take_snapshot` 确认头像/昵称等）。
3. 若多账号/多租户：确保进入正确的组织/空间后再继续。

## 打开缺陷列表（任意 TAPD 项目）

通过 Chrome DevTools MCP 在已打开的 Chrome 中操作：

1. 使用**用户提供的缺陷列表 URL** `navigate_page`，或从 TAPD 顶部导航进入 **项目/空间** → 选择**已确认名称**的项目。
2. 进入 **缺陷** → **缺陷列表** 页面。

**可选示例（仅作仓库内历史参考；参数可能失效，不得作为未确认项目时的默认入口）：**

- 外视镜项目列表示例：`https://www.tapd.cn/tapd_fe/30689687/bug/list?confId=1130689687001002009`

> 若 URL 失效或参数变化：以 UI 导航为准，不要依赖旧 queryToken。

## 设置筛选（处理人 + 状态）

### 处理人（默认：当前登录用户）

1. 点击 **过滤**。
2. 在过滤条件里找到 **处理人**。
3. 选择 **当前登录用户**（或下拉中与约定一致的人员）。
4. 应用后确认列表计数变化。

### 状态（默认：新 / 接受(处理) / 重新打开）

优先方式（在页面上直接多选状态）：

1. 在过滤条件里找到 **状态**。
2. 多选：**新**、**接受**（或页面显示为“接受/处理”）、**重新打开**（或用户确认的其他状态）。
3. 应用过滤。

备选方式（若页面不支持多选或 UI 不易操作）：

- 先按处理人过滤，再在本地文档里**按状态字段二次筛选**并标注“本页数据”。

## 抓取每条缺陷详情（弹窗预览）

TAPD 常见行为：在列表中点击标题会打开**同页弹窗预览**（URL 会出现 `dialog_preview_id=bug_...`），不一定跳转到独立详情页。

对每一条 Bug（建议按列表顺序，或按用户指定的 ID 顺序）执行：

1. 在列表中点击该条 **标题链接**打开详情弹窗。
2. 在弹窗中抓取内容并分流用途：
   - **「一、列表总览」用**：可从列表行或弹窗基础信息区读取状态、优先级、严重程度、处理人、创建时间等（字段名因模板而异）。
   - **「二、每条 Bug 详细信息」用**：仅从**详细信息**区映射下列 5 项（TAPD 字段名可能为「前置条件」「复现步骤」「测试步骤」等，按语义归入对应列）：
     - **标题**（可与列表标题一致；以详情为准）
     - **前置条件**（对应常见「前置条件」等）
     - **操作步骤**（对应「复现步骤」「测试步骤」等；保留原文编号与换行）
     - **预期结果**
     - **实际结果**
3. 关闭弹窗，继续下一条。

### 建议抓取字段（标准化）

- **第一节「列表总览」表**：仍建议包含 TAPD ID（或序号+标题可唯一定位）、标题、发现版本、严重程度、预计结束、优先级、状态、创建人、创建时间等（以列表页可得的为准）。
- **第二节「每条 Bug 详细信息」**：**仅**输出以下 5 项（没有则写 `-`），**不得**在该分块内再输出状态、优先级、模块、附件等其它列：
  - **标题**
  - **前置条件**
  - **操作步骤**
  - **预期结果**
  - **实际结果**

## 生成最终 Markdown 文档

- 只生成**一份**文档，包含列表总览 + 每条详情 + 说明。
- 保存路径：`<工作区根目录>/BUGFIX/<项目显示名>-<范围简述>-Bug详情-YYYY-MM-DD.md`（创建 BUGFIX 目录后再写入）。

输出结构建议：

1. **列表总览表**（一页/多页都可合并到同一个表；建议包含：标题、发现版本、严重程度、预计结束、优先级、状态、创建人、创建时间）
2. **每条 Bug 详情分块**（仅含：标题、前置条件、操作步骤、预期结果、实际结果；见下模板）
3. **说明**（数据范围、筛选条件、抓取时间、是否仅本页等）

### Markdown 模板（可直接复用）

将 `<项目显示名>`、筛选与数据范围替换为与用户确认一致的表述。

```markdown
# <项目显示名> - Bug 详情（结构化）

**筛选条件：** <与用户确认一致，例如：处理人 = 当前登录用户；状态 ∈ 新、接受/处理、重新打开>
**数据范围：** <例如：缺陷列表第 X 页 / 第 1~N 页 / 指定 Bug ID：...>
**生成日期：** YYYY-MM-DD

---

## 一、列表总览

| 序号 | 标题 | 发现版本 | 严重程度 | 预计结束 | 优先级 | 状态 | 创建人 | 创建时间 |
|------|------|----------|----------|----------|--------|------|--------|----------|
| 1 | ... | ... | ... | ... | ... | ... | ... | ... |

---

## 二、每条 Bug 详细信息

本节每条只保留下列字段；其它信息（状态、优先级、附件等）只出现在「一、列表总览」，不得写入本节。

### Bug #1

| 字段 | 内容 |
|------|------|
| **标题** | <标题> |
| **前置条件** | <对应 TAPD 前置条件等；无则填 `-`> |
| **操作步骤** | <复现步骤/测试步骤原文，保留编号与换行> |
| **预期结果** | <预期结果原文> |
| **实际结果** | <实际结果原文> |

（后续 Bug 重复上表结构。）
```

## 质量检查（生成后自检）

- [ ] 汇总表条数与约定范围一致（或在“说明”里明确只覆盖第 X 页 / 指定 ID）
- [ ] 第一节总览行与第二节条数一致（或说明中写明例外）
- [ ] 第二节每条仅含 5 列：标题、前置条件、操作步骤、预期结果、实际结果；操作步骤与预期/实际尽量保留原文（含编号）

## 常见问题与处理

- **点击标题不跳转，只出现弹窗**：正常；以弹窗内容为准抓取。
- **状态字段显示为“接受/处理”**：在文档里统一归并到“接受/处理”即可。
- **页面不支持多选状态**：先按处理人过滤，再在文档里按状态二次筛选并明确“本页数据”。
- **BUGFIX 目录不存在**：在写入文档前先创建 `<工作区根目录>/BUGFIX`，再保存 Markdown 文件。
