# Unit Test Generator

为指定源码生成可编译、可运行的单元测试。测试基础设施已就绪：勿新建测试工程、勿改 sln/包引用，除非用户明确要求。

优先测纯逻辑；强依赖 I/O、UI、硬件时先评估可测性，不可测则提最小改造，禁止写假测试凑绿。

## 前提

- 仓库中已有对应测试项目与运行方式；先定位现有测试再写入。
- 命名、框架、目录、断言风格以**仓库现有测试**为准；若有 `unit-test-standards` 等 Rule，一并遵守。
- 无现成测试可参考时，采用下文默认约定，仍不主动搭建工程。

## 工作流（必须逐步执行）

```
Task Progress:
- [ ] 1. 输入确认
- [ ] 2. 定位测试落点
- [ ] 3. 可测性分析
- [ ] 4. 改造建议（仅不可测时，需确认）
- [ ] 5. 用例设计
- [ ] 6. 生成测试
- [ ] 7. 执行验证并迭代修正
- [ ] 8. 交付摘要
```

### 1. 输入确认

- 需要目标源文件/类型（`@` 引用或路径）。无则询问，勿整库批量生成。
- 多个目标时按「纯逻辑 → 领域/校验 → 需 Mock 的应用逻辑」顺序逐个处理。

### 2. 定位测试落点

在仓库中查找与被测程序集对应的现有 `*.Tests`（或同等）项目：

1. 打开已有同类测试，复制其命名空间、目录分层、using、断言风格。
2. 确认运行命令（常见：`dotnet test <测试csproj> --filter ...`；以仓库实际为准）。
3. 找不到对应测试项目 → 告知用户并停止，**不**擅自创建测试工程。

### 3. 可测性分析

| 类别 | 判定 | 处理 |
|------|------|------|
| 可测 | 纯函数/可隔离逻辑，无外部 I/O 或已可注入 | 直接写测试 |
| 可抽 | 逻辑嵌在 I/O/UI/硬件回调中，可抽无副作用片段 | 步骤 4 |
| 不可测 | UI 视图、启动流程、实时流、第三方原生直连等 | 说明原因并跳过 |

输出：可测方法列表 + 外部依赖说明。

### 4. 改造建议（仅不可测且值得测时）

提出**最小**可测性改造，**用户确认后再改产品代码**：

- 抽出无副作用的纯逻辑（解析、校验、状态机、计算）；I/O 留在原处。
- 若需测 `internal`：用项目已有的可见性机制（如 `InternalsVisibleTo`），目标程序集名与现有测试项目一致。
- 禁止：改业务语义凑绿、空 catch、为测而测的无意义抽象。

用户拒绝 → 只交付分析与用例表，不生成假测试。

### 5. 用例设计

先写用例表再编码：

| Method | Scenario | Expected |
|--------|----------|----------|
| ... | 主路径 | ... |
| ... | 边界 | ... |
| ... | 错误/非法输入 | ... |

覆盖主路径 + 边界 + 错误。风格示例见 [examples.md](examples.md)。

### 6. 生成测试

- 写入步骤 2 定位的测试项目；类/方法命名跟随仓库惯例。
- **默认约定**（仅当仓库无先例时）：
  - 类 `{TargetClass}Tests`；方法 `{Method}_{Scenario}_{ExpectedOutcome}`
  - 框架跟随现有测试（常见 xUnit：`[Fact]` / `[Theory]`）
  - 有意义断言；异步用 `await`，禁止 `.Result` / `.Wait()` 阻塞
  - 外部依赖 Mock；纯逻辑禁止无必要 Mock
- **不生成**：UI 控件/视图、应用启动、需真机/真硬件才能验证的路径。

### 7. 执行验证并迭代修正

```text
dotnet test <已有测试项目.csproj> --filter "FullyQualifiedName~{ClassName}"
```

按仓库习惯调整命令。失败则读错误 → 修测试或已确认的抽取逻辑 → 重跑，直至通过。  
禁止删断言、`Assert.True(true)`、吞异常“通过”。

### 8. 交付摘要

1. 新增/修改文件列表  
2. 用例数量  
3. 测试运行结果  
4. 未覆盖的 I/O / UI / 硬件依赖（若有）  
5. 若改了产品代码：一句话说明抽取点  

## 生成优先级（默认）

| 优先 | 目标 | Mock |
|------|------|------|
| 高 | 纯函数、解析、校验、计算 | 无 |
| 中 | 领域模型、无 UI 的状态逻辑 | 通常无 |
| 低 | 需注入依赖的应用/VM 逻辑 | 对接口 Mock |
| 跳过 | UI、启动、实时设备/原生直连 | — |
